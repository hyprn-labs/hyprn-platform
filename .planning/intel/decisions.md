## ADR-0001: Agent fleet — background coding agents on Claude Team seats in a separate project
- source: docs/adr/0001-agent-fleet.md
- status: locked (Accepted, 2026-10-12). Section 4 "Agent host": machine size and always-on operation SUPERSEDED by ADR-0002; the remainder stands.
- decision: Chosen options L1, P1, G1, S1.
  1. Licensing (L1): one Claude Team seat per agent, unmodified Claude Code CLI signed in with that seat; no OpenAI seats for agents (OpenAI seats are single-user, no shared credentials); third-party harnesses use API keys only. A seat is an identity plus usage quota, not a role; roles come from instructions in `agents/roles/`. Platform owner is Team Owner and holds a seat (covers two-seat minimum). Overflow through the Team plan's monthly API credits (pooled, capped 500 USD/month, do not cover Claude Code) via API key for Agent SDK or Managed Agents; optional low-cost tier with open-weight models via API key. Extra usage not enabled at first. A second agent is added only after Anthropic's human answer confirms seat assignment to an agent identity; any change to who drives agents is checked against that answer first.
  2. Identities per agent (every display name ends with "(AI agent)"; agent first names allowed only in these per-agent identities, a deliberate exception to `conventions/`; cloud resources stay role-named): email `<name>@agents.hyprn.ai` (Google Group, founders as members); Claude Team seat with email-code sign-in, `agents.hyprn.ai` an allowed domain, dedicated browser profile; Slack one app per agent `<Name> (AI agent)` on Socket Mode; GitHub one App per agent `hyprn-<name>` committing as `hyprn-<name>[bot]`; host one Linux user `<name>`.
  3. Project `hyprn-agents` (random suffix only if ID taken): own project in its own folder, same organization and billing account as staging and prod; engineering tooling, not an environment (no product workload, product data or deployment authority; "no standing third environment" unaffected). Its principals hold no role outside the project and no staging/prod principal holds a role inside it (checked by organization-wide IAM search, re-checked when staging and prod are created). Default service accounts get no automatic Editor role; no service-account keys; monthly budget 100 EUR alerting at 50, 80, 100 %. Set up manually with reviewed `gcloud` steps in `runbooks/agents/`, then codified in `infra/agents/` with its own state and imported.
  4. Agent host (size/always-on superseded by ADR-0002): one VM `hyprn-agents-host-01`, 100 GB balanced disk, Debian 12, Shielded VM, no public IP; SSH only through IAP with OS Login, project-wide SSH keys blocked, outbound through Cloud NAT. One Linux user per agent (private home, no sudo) with rootless Docker per user (shared `docker` group would be root-equivalent; Claude Code sandbox covers shell commands only, so Linux users are the inter-agent boundary). Agent users cannot reach the metadata server; a root-owned helper fetches each agent's secrets from Secret Manager with the VM identity and writes them readable only by that agent. Claude Code signed in with `/login` per agent user. One persistent session per agent in tmux under systemd. One task = one branch `agent/<name>/<slug>` = one git worktree = one draft pull request; ports, Compose project names and test databases set per worktree via environment variables (product support is product work, outside this decision). No production credentials on the host.
  5. GitHub (G1): GitHub Team plan required (draft PRs, protected branches, enforced code owners on private repositories). Each agent App: Contents RW, Pull requests RW, Metadata R; no Workflows, no Administration; selected repositories only; private key in password manager and Secret Manager; host mints one-hour installation tokens. Ruleset on `main` is the control (Contents write allows merging): PR required, approval from code owners that are human teams only, stale approvals dismissed, no force push, no bypass for any App. Signed commits not required for now. Agents can open PRs only once repositories exist on GitHub.
  6. Slack control (S1): one persistent Claude Code session per agent with a Slack channel plugin (Claude Code channels, research preview). Team Owner sets once, organization-wide, in the admin console: `channelsEnabled`, `allowedChannelPlugins` (our marketplace and plugin), `strictKnownMarketplaces`, `disableBypassPermissionsMode`; reviewed copy in `agents/policy/`. The community Slack plugin is audited and vendored into `agents/marketplace/` with its licence and upstream commit (see WARNING in INGEST-CONFLICTS.md: audit outcome diverged). Sender allowlist: platform owner's Slack user ID only; other senders dropped before reaching the session; same allowlist for permission replies; agents invited only to working channels. Permission rules and sandbox always on; risky actions relayed to Slack for approval; skip-all-permissions mode disabled.
  7. Measurement: first week with the first agent: per-agent token and cost metrics via Claude Code OpenTelemetry export to a collector on the host, Team admin analytics and spend report, daily log of seat-limit hits. Owner then decides, with no preset thresholds, Standard vs Premium seats, seats vs API keys, and when to add the next agent; recorded in a follow-up ADR.
  Confirmation checks (in `tests/agents/`, before an agent starts work and after each host/project change): no `hyprn-agents` principal role outside the project; agent user cannot reach metadata server, read another agent's home or use another agent's Docker; `--dangerously-skip-permissions` refused; non-allowlisted Slack sender ignored and non-allowlisted approval rejected; agent App cannot merge a PR or push to `main`; no user credentials, key files or staging/prod roles on the host.
- scope: background coding agents, Claude Team seats, Claude Code CLI, OpenAI licensing, Google Cloud project hyprn-agents, agent host VM hyprn-agents-host-01, GitHub Apps and branch rulesets, Slack channel plugin, Linux agent users and Docker, Secret Manager, OpenTelemetry measurement

## ADR-0002: Agent host on demand, woken from Slack
- source: docs/adr/0002-agent-host-on-demand.md
- status: locked (Accepted, 2026-10-12). Supersedes ADR-0001 section 4 machine size and always-on operation only.
- decision: Chosen H3 (larger host on demand plus a small always-on wake service on Slack Socket Mode); rejected H1 always-on e2-standard-4, H2 manual start only, H4 public HTTPS wake endpoint (against the outbound-only rule).
  - Host `hyprn-agents-host-01`: `t2d-standard-8` (8 physical cores, 32 GB), same 100 GB balanced disk, pinned Debian 12, no public IP.
  - Host stops itself after 30 minutes with no agent work and no SSH session (guest shutdown, no cloud permission needed); on boot each agent's session resumes under systemd.
  - Wake service `hyprn-agents-wake-01`: `e2-micro`, always on, no public IP, outbound Socket Mode only. Connects to an agent's Slack app only while the host is stopped, so it never takes events from a running agent. On a message from the allowlisted sender it replies that the agent is waking, starts the host and disconnects. Code in `agents/wake/`.
  - Wake identity `hyprn-agents-wake`: custom role with `compute.instances.get`, `start`, `stop` granted on the host instance only, plus log and metric writing; Slack tokens from Secret Manager per secret.
  - Host can also be started with `gcloud compute instances start` or the Cloud console app.
  - Cost (Cloud Billing catalog 2026-10-12, europe-west1, EUR): t2d-standard-8 about 0.33/h; e2-micro about 6/month; 100 GB balanced disk about 9/month; about 75-80/month at 8 h/day on 22 days, within the 100 EUR budget.
  - Confirmation: allowlisted sender message to a stopped agent starts the host and the agent answers (others do not); wake service holds no Slack connection while host runs; wake identity refused any action other than get/start/stop on the host; host stops after idle period and keeps disk contents.
  - Known estimate: about a minute from first Slack message to reply when stopped (to be measured).
- scope: agent host hyprn-agents-host-01, wake service hyprn-agents-wake-01, Slack Socket Mode, wake identity hyprn-agents-wake, Secret Manager, t2d-standard-8 machine type, e2-micro machine type, persistent disk
