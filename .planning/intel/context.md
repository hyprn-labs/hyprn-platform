## Repository overview
- source: README.md
- The company's cloud platform, able to host HYPRN MVP and later products: Terraform, staging and prod environments, cloud identities and access, governance and repository protections, the fixed deployment contract, the host reconciler, policies and runbooks. No product code; the product lives in `../hyprn-mvp`.
- Ownership: product owns scientific and API contracts, data schema migrations, health behaviour and images; platform owns allowed deployment classes, cloud bindings, trust policy, host templates and the desired release per environment. Terraform owns cloud resources; the reconciler owns rendered runtime state; neither rewrites the other's artifacts.
- README states "Status: skeleton. Implementation starts with the cloud work, after the local edition" (outdated per runbook records; see INFO in conflicts report). Platform spec in `docs/specs/`; agent fleet planned in `docs/plans/agent-fleet.md`.
- Layout: `bootstrap/ governance/ contracts/v1/ conventions/`, `infra/modules/{environment,host}/ infra/environments/{staging,prod}/`, `environments/{staging,prod}/ host/ policies/ tests/ catalog/ runbooks/`, `agents/ infra/agents/` (agent fleet, ADR-0001), `docs/{specs,adr,plans}/ .github/workflows/ (later)`.

## agents/marketplace: audit record and design
- source: agents/marketplace/README.md
- Our Claude Code plugin marketplace `hyprn-agents` (`.claude-plugin/marketplace.json`), installed root-owned at `/opt/hyprn-agents/marketplace` on the agent host; agents need no access to this repository. Plugin `slack` (`plugins/slack/`): Claude Code channel to Slack, one agent per Slack app.
- Audit (2026-10-12) requirements from ADR-0001 section 6: Socket Mode only; sender allowlist by Slack user ID also for permission replies; tokens read from files; outbound only to Slack; pinned dependencies; licence allowing our use. Candidates: `Reef-Digital/claude-code-slack` (Apache-2.0) rejected (allowlist in an agent-writable file with "empty list = anyone", npm caret-range installs at every start, needs Bun, approvals through its own shell hooks); `Muneshige1567/claude-channel-slack` rejected (no licence).
- Decision recorded in this DOC: own server `plugins/slack/server.py`, about 300 lines, standard library plus Debian `python3-websocket`: MCP over stdio declaring `claude/channel` and `claude/channel/permission`, MCP revision `2025-06-18`; inbound only through Socket Mode, envelopes acknowledged and deduplicated by event ID; delivers only DMs and mentions from senders in root-written allowlist `/run/hyprn-agents/slack-allowed-users.json`, others dropped and logged without content; permission requests go to the allowlisted user's last conversation, only `yes <id>` / `no <id>` from an allowlisted sender for an ID Claude Code issued becomes a verdict; tokens from `/run/hyprn-agents/secrets/<agent>/slack.env` (tmpfs, 0400, root-written); network calls only to `slack.com` and the Socket Mode URL Slack returns.
- Residual risk (as stated): server runs as the agent user, so an already-compromised agent could alter its installed copy or use its own bot token directly; the allowlist protects the session from other people's messages; the Linux user boundary limits what a compromised agent can reach.
